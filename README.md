# Healthcare Test Data Lab

Test data for hospital and payer integrations that never touches a real patient. Built on
[Synthea](https://github.com/synthetichealth/synthea), and made fit for FHIR, HL7 v2 and X12 integration testing.

Synthea is the right starting point: every patient is simulated, so there is no PHI to leak. Out of the box it is
not yet a test dataset. When we tested it the way a hospital would (3 Oct 2026, seed 42, Massachusetts):

| Finding | Measured | After this lab |
|---|---|---|
| Facility NPIs that belong to real, registered organizations (CSV export, checked in NPPES) | 158 of 160 | replaced with unissuable synthetic NPIs |
| Real facility phone numbers in the FHIR output | 480 | 0 |
| US Core 6.1.0 validator errors on 3 patient bundles | 2,412 | 0 |
| US Core 6.1.0 resource profiles never populated | 12 of 49 | documented; add what your workflow needs |
| Patient names with numeric suffixes ("Dian810") | 56 of 56 | 0, including inside clinical notes |

Full write-up: [Test Hospital Integrations Without PHI: What We Found in Synthea Data](https://nirmitee.io/blog/test-hospital-integrations-without-phi-synthea/).
Every number above is regenerated by a script in this repository; see [FINDINGS.md](FINDINGS.md).

## What the lab does

| Step | What it does |
|---|---|
| `lab.scrub` | Replaces the real facility names, street addresses, phone numbers and NPIs Synthea copies from public directories (deterministic mapping); strips numeric name suffixes, including inside base64 clinical notes; removes Synthea-only extensions that make every Patient fail US Core |
| `lab.safety` | Exits 1 if any SSN, NPI, phone or email has a format that could have been issued for real; `--nppes` also asks the NPPES registry. Use it as a CI gate before a dataset is shared |
| `lab.messify` | Injects the defects real feeds carry (local lab codes, duplicate patients, weights in pounds, partial birth dates, MRNs without a system, missing encounter links) and writes a manifest of every change, so a test can assert that each defect was caught. `--profile strict` adds spec violations |
| `lab.to_hl7v2` | Writes HL7 v2.5.1 ADT^A04 and ORU^R01 messages for the same patients |
| `lab.load` | Loads bundles into a FHIR server in dependency order and checks the server's counts against the manifest |
| `lab.pipeline` | All of the above in one command |

## Quick start

Needs Docker and Python 3.9+. No Java on the host: Synthea and the HL7 validator run in `eclipse-temurin:17-jre`.

```bash
curl -L -o tools/synthea-with-dependencies.jar \
  https://github.com/synthetichealth/synthea/releases/download/master-branch-latest/synthea-with-dependencies.jar
docker run -d --name synthlab-hapi -p 127.0.0.1:8090:8080 hapiproject/hapi:latest

python3 -m lab.pipeline --patients 50 --seed 42 --rate 0.1 --out out/run --fhir-base http://localhost:8090/fhir
```

Output in `out/run/`: `synthea/` (raw), `fhir-clean/`, `fhir-messy/` with `defects.manifest.jsonl`, `hl7v2/`,
`summary.json`. Each step also runs alone: `python3 -m lab.<step> --help`.

US Core validation with the official HL7 validator: `scripts/validate_us_core.sh out/run/fhir-clean out/run/validation 3`.

## What each check does and does not catch

- `lab.safety` catches identifiers whose **format** could be real. It does not detect a real name, a real street
  address or a pasted chart note. A clean scan means "no real-looking identifiers", which is weaker than "no PHI".
- An NPI with a valid check digit is well formed, not fake. `--nppes` checks that it is unregistered.
- `scripts/validate_us_core.sh` runs without a terminology server, so codes are not checked against value sets.
- Only defects on the Patient or on lab results reach the HL7 v2 output. Duplicates, weights in pounds and missing
  encounter links stay FHIR-only.
- HAPI FHIR 8.12.0 with default settings rejects a dangling reference but stores a time without a time zone.
